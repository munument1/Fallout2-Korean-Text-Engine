# sfall과 한국어 출력 엔진의 분리

## 어떤 기능이 따로 동작하나?

- **한국어 출력:** 한국어 호환으로 수정한 Fallout 2 실행 파일, `fallout2font.dll` 브리지, 별도로 소유한 기존 CJK 글꼴 DLL 및 Galmuri 글꼴이 담당한다.
- **sfall:** 사용자가 이미 설치한 게임 기능 확장 모듈이다. 한국어 출력 모듈의 소스는 sfall 함수에 직접 의존하지 않는다.
- **번역 데이터:** 각 게임·모드의 한국어 패치 저장소에서 별도로 설치한다. `TranslationsINI`는 sfall 자체에 표시되는 메시지의 번역 설정이다.

## sfall이 없는 경우

공식 sfall `ddraw.dll`은 필수 입력이 아니다. 설치기는 검증된 게임 EXE 및 CJK 원본 파일만 확인하고, sfall용 `ExtraCRC`, `TranslationsINI` 또는 `HiResMode` 설정을 건드리지 않는다. `ddraw.ini`가 없어도 출력 엔진을 구성할 수 있다.

**중요:** 소스 의존성 및 설치 의존성을 분리한 상태다. sfall이 없는 실제 Fallout 2 실행·플레이 호환성 검증은 별도로 필요하다. 이 기능만으로 모든 게임/모드가 sfall 없이 동작한다고 보증하지 않는다.

## 모드에 sfall이 이미 있다면

- 모드 설치본의 `ddraw.dll`을 **변경하거나 덮어쓰지 않는다**.
- 기본 설치는 **`ddraw.ini`를 전혀 변경하지 않는다.** 수정된 EXE의 CRC가 기존 설정에 등록되어 있지 않으면 설치를 중단한다.
- 사용자가 **고급 옵션에서 sfall 호환 설정 수정을 명시적으로 허용**한 경우에만 수정 EXE용 `ExtraCRC`를 추가한다. 이때 비순정 모드의 `TranslationsINI`도 설정할 수 있다.
- 기존 외부 HRP와 충돌하는 일부 모드의 `HiResMode` 역시 **고급 호환 옵션을 명시적으로 켰을 때만** 수정한다.
- 정확히 검증한 sfall 4.5.1 이외의 버전도, 32비트 DLL이며 sfall 형식의 INI가 존재한다면 사용할 수 있도록 하되 **실제 게임 호환성은 검증되지 않았다**고 안내한다. 알 수 없는 `ddraw.dll`이나 INI가 없는 설치에는 무작정 쓰지 않는다.

## 필요한 파일

게임 본체, 각 모드, `FO2_UPU_CHT_v34`에서 별도로 확보한 기존 CJK EXE/DLL은 여전히 필요하다. 이는 sfall 의존성과 구분되는 기존 한글 출력 방식의 요구사항이다.

## 확인 항목

1. sfall 없는 순정 EXE 설치에서 `ddraw.dll`·`ddraw.ini`를 생성하거나 변경하지 않을 것.
2. sfall 있는 모드에서 `ddraw.dll`의 해시가 설치 전후 동일할 것.
3. 일반 설치에서 `ddraw.ini`의 바이트가 하나도 바뀌지 않을 것. 명시적으로 고급 호환 옵션을 켜야 `ExtraCRC`를 변경할 것.
4. 설치·복구, 자산 무결성, 미지원 EXE 거부가 그대로 동작할 것.
5. 사용자가 소유한 실제 게임 파일로 원본/Fallout Et Tu/RPU 등 주요 모드의 시작 메뉴, 한글 출력, 게임 저장·불러오기, 복구를 수동으로 점검할 것.

전수 플레이 검증이 완료되기 전에는 sfall 없는 모드 전체에 대한 호환성 보증으로 해석하지 않는다.

## 아직 해결되지 않은 근본 문제

현재 설치 방식은 기존 CJK 실행 파일의 바이너리 코드를 사용한다. 이로 인해 EXE 해시/CRC가 원본과 달라진다. 따라서 **sfall을 필수로 쓰는 모드에서 `ExtraCRC` 변경 없이 자동으로 동작한다고 보장할 수 없다.** 인식되는 기본 CRC에 포함되는지 버전별로 검증하거나, 향후 게임 EXE를 변경하지 않는 별도 로딩 방식/폰트 처리 구조를 검토해야 한다. 설치기에서 INI 수정을 막는 것은 충돌 방지 조치이지 새로운 엔진 아키텍처의 완전한 구현이 아니다.
