# 독립형 엔진 후속 검증 계획

작성일: 2026-10-22. 기준: main `993a8ca`, 정식 배포 v1.2.3.

## 기준 버전과 완료된 범위

PR #11의 `a161641`은 특정 RPU EXE 해시만 허용하던 과거 구현이다.
이후 범용 구조 검사와 설치 안전성 처리는 PR #16, #18, #19를 통해 main에
반영되었다. PR #11이 Draft로 남아 있다는 사실만으로 현재 배포판의 지원
범위를 판정하지 않는다. 현재 Et Tu는 구조 검사 대상이고 Resurrection은
기존 KR1.1 유지 대상으로 명시적으로 제외한다.

- Windows 네이티브 DLL/설치기 빌드, 번들 자체 검사, 한글 11,172자 및 합성
  대화 줄바꿈 프로브는 기존 CI 범위다.
- 실제 RPU 대화문 12,000개의 줄바꿈 검사는 문자 경계와 바이트 보존을
  확인했다. UI 높이, 스크롤, 선택지 접근 가능 여부는 증명하지 않는다.
- RPU 복사본의 두 EXE 설치·복구와 고해상도 메인 메뉴 확인은 기존 기록이다.
- 기본 새 게임·저장·재시작·로드 기록은 RPU 퀘스트/전투 진행 상태의 전수
  보존 검증을 대신하지 않는다.
- 현재 CFG 복구는 설치기가 언어만 변경했다는 것을 검증할 수 있으면,
  게임 중 바뀐 볼륨 등 설정을 보존하고 언어 변경만 되돌린다. 변경된 모든
  설정을 일괄 거부하는 과거 동작을 합격 기준으로 사용하지 않는다.

## 이번 자동검사의 범위

`tests/test_native_transaction.py`는 PE 검사와 패치 결과를 모킹한 합성 파일로
실제 설치·백업·복구 함수를 호출한다. 실제 EXE ABI, HRP 로딩 또는 게임플레이
호환성을 검증한 것으로 해석하지 않는다.

추가한 네 사례:

1. 서로 다른 두 원본 EXE 중 두 번째 기록 실패: 첫 EXE까지 원복되고,
   불완전 백업이 없어야 한다. 재설치·복구 후 각 EXE는 각자의 원본으로
   돌아와야 하며 저장 파일·RPU DAT·HRP 파일은 유지되어야 한다.
2. 설치 후 두 번째 EXE 변경: 사전 검사와 실제 복구 모두 다른 EXE를
   되돌리기 전에 중단해야 한다.
3. 두 번째 EXE 백업 손상: 모든 파일을 변경하지 않고 중단해야 한다.
4. 설치된 글꼴 DLL 변경: 두 EXE를 포함해 아무 파일도 복구하지 않아야 한다.

이번 Linux 실행 결과: 총 75개 중 52개 통과, 소유 게임 입력이 필요한 23개
생략, 실패 0개. Windows DLL 컴파일이나 실게임을 새로 수행한 결과는 아니다.

## 남은 실게임 검증과 합격 기준

아래 횟수·시간은 제안하는 최소 실행량이며 아직 통과 기록이 아니다.
정상 실행되는 동일 RPU 버전의 패치 전 상태와 비교하고, 시험용 저장 슬롯을
분리한다. 실제 대사 MSG ID/원문과 화면의 마지막 문장까지 대조한다.

| 순서 | 실행할 검증 | 합격 기준 |
| --- | --- | --- |
| 1. 장문 대화·선택지 | 장문 답변, 3개 이상 선택지, 여러 줄 선택지, 이름·숫자를 포함한 동적 문자열. 1024x768과 더 좁은 지원 화면에서 마지막 선택지까지 조작 | 글자·마지막 문장 손실과 겹침 없음. 넘치는 내용은 게임이 제공하는 넘김/스크롤로 접근 가능. 마우스·키보드로 표시된 분기를 정확히 선택 |
| 2. 전투 | 근접·원거리, 명중·빗나감·치명타·사망 로그와 머리 위 대사. 메시지 연속 발생 후 대화·인벤토리 전환 | 첫 한글·접두 기호·색상 정상. 로그 접근과 턴 진행·전투 종료 정상. 충돌·잔상 없음 |
| 3. 진행 상태 저장 | 같은 RPU 버전의 패치 전 저장본 로드. 퀘스트 변경·전투·아이템 변동 후 저장→프로세스 종료→재실행·로드 3회. 두 EXE로 같은 시험 저장본 로드 | 기록한 퀘스트 단계·동료·아이템·위치 유지. 재시작 후 한글 정상. 저장본 읽기 오류 없음 |
| 4. 장시간·화면 전환 | 2시간 이상 대화·전투·지도 이동·핍보이·인벤토리·거래·저장/로드 반복. 처음과 끝에 같은 장문 대화 확인 | 충돌·멈춤·시간 경과에 따른 글꼴/줄간격 변화 없음. 메모리가 반복마다 계속 증가하는 양상 없음 |
| 5. 플레이 후 복구 | 관리 대상 파일이 그대로인 정상 경로 및 게임이 CFG 설정을 변경한 경로 | 정상 경로는 원본 SHA 복원. CFG 병합 경로는 사용자 설정 유지·설치기 언어 변경만 원복. 저장·번역 데이터 보존. 원래 실행기 기동 정상 |
| 6. 추가 조합 | RPU 원래 HRP·sfall 조합을 먼저 완료한 뒤 실제 사용하는 추가 모드를 하나씩 검증 | 기존 DLL·모드 데이터 유지, ExtraCRC 기존 값 유지, 모드 기능과 대화·전투·저장 정상 |

## 다른 릴리즈와 모드

- 다른 RPU 릴리즈는 전체 EXE 해시가 달라도 ABI가 호환되면 설치 가능하다.
  허용 여부만으로 합격 처리하지 않고 해당 HRP·sfall 조합의 1~3번을 확인한다.
- ABI 비호환 EXE가 하나라도 있으면 어느 EXE도 변경하지 않는 것이 합격이다.
- Et Tu는 원본에서도 HRP/sfall 고해상도 충돌 기록이 있다. 먼저 같은 설정의
  패치 전 실행을 확보한 다음 엔진 적용 전후를 비교한다.
- Nevada/Olympus의 Extended sfall은 유지한다. 일반 sfall로 교체해 검증하지 않는다.
- Resurrection은 지원 확대 시험에서 제외하고 기존 KR1.1을 유지한다.

각 결과에는 설치기·DLL 해시, 원본/패치 EXE 해시, 게임·HRP·sfall 버전,
해상도, 활성 CFG, 사용 저장본, MSG ID, 화면 증빙 및 실패 재현 순서를 남긴다.
