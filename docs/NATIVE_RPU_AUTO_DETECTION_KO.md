# 독립형 한글 엔진: RPU 자동 판별 및 고해상도 패치 보존

작성일: 2026-10-17

## 기존 오류의 원인

v1.2.0-alpha.4 독립형 설치기는 순정 Fallout 2 US 1.02d 실행 파일의
SHA-256만 허용하고 게임 종류에서 RPU를 선택할 수 없도록 제한했습니다.
따라서 RPU에서 게임 종류 오류가 발생하는 것이 정상적인 안전 차단이었습니다.

사용자 컴퓨터의 D:\Fallout 2\RPU를 **읽기 전용으로 분석**하여 다음을 확인했습니다.

| 항목 | 순정 US 1.02d | 사용자 RPU |
| --- | --- | --- |
| EXE SHA-256 | 581c09c20fee70edc09ec412ee034e62e89cdefa13092e534ddd17d23f8163cb | 048684f802b05859e2b160fa358be1b99075bf31b49a312a536645581aa16b5f |
| EXE 크기 | 1,189,888바이트 | 1,189,888바이트 |
| PE 섹션 | 6개 | 동일 |
| 게임 시작 엔트리 | 0x4E4480 | 동일 |
| 자체 엔진 후킹 지점 | 0x4CAF22 | 원본 명령어 동일 |
| 원본 wordWrap 함수 | 0x4BC6F0 | 원본 명령어 동일 |
| 수정된 바이트 | 기준 | 38바이트 |

RPU의 38바이트 수정은 고해상도 f2_res.dll을 읽기 위한 기존 HRP 부트스트랩입니다.
원본 순정 EXE로 교체하면 이 기능을 잃을 수 있으므로 **그냥 덮어쓰지 않습니다.**

## 변경 내용

1. 독립형 설치기에서 **수동 게임 종류 선택을 제거**하고 폴더를 자동 인식합니다.
   검증된 EXE의 해시 및 mods/rpu.dat 존재 여부를 사용합니다.
2. 순정 EXE와 **위 정확한 RPU HRP SHA-256만** 허용합니다.
   다른 EXE/HRP/모드 버전은 추측해서 패치하지 않습니다.
3. RPU의 기존 38바이트를 그대로 보존하며 자체 PE 섹션(.krinit)에
   독립형 한국어 초기화 코드를 추가합니다.
4. RPU에서 fallout2.exe와 fallout2HR.exe가 동일한 검증 원본이라면
   두 파일을 모두 패치하고 모두 복구 대상으로 등록합니다.
   두 EXE가 서로 다르면 어느 쪽도 변경하지 않고 오류를 안내합니다.
5. f2_res.dll, f2_res.ini, mods/rpu.dat와 RPU 메뉴 설정을 보존합니다.
6. sfall 설정은 다른 항목을 보존하면서 ExtraCRC만 추가합니다.
7. 변경할 원본 EXE 및 INI 파일은 안전 복구 폴더에 백업합니다.

## 시험 결과

- 실제 RPU 폴더를 별도 경로에 완전히 복사해 테스트했습니다.
- 자동 폴더 판별, 자체 DLL의 설치 및 두 EXE의 동일한 패치 결과 확인.
- 설치 후 1024x768 고해상도 화면에서 한글 메인 메뉴까지 실제 실행 확인.
- 단위 테스트에서 기존 HRP 후킹 바이트가 유지되는지 검증했습니다.
- 사용자의 D:\Fallout 2\RPU 원본은 변경하지 않았습니다.

## 지원 범위

현재 지원은 **정확히 이 실행 파일과 순정 1.02d**에 한정됩니다.
RPU의 다른 HRP 버전, Et Tu 등 다른 엔진 변형까지 자동 호환되는 것은 아닙니다.
모든 NPC 대화·장시간 플레이·전투·지도에 대한 전수 테스트는 아직 필요합니다.
기존 정식판 및 alpha.4 릴리즈는 수정하지 않습니다.
