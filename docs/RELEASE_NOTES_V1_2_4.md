# Korean Text Engine v1.2.4 — RPU 외형 설명

RPU 이슈 #4의 추가 자료에서 제보자는 v1.2.3을 사용했고 기술 목록은 정상이지만 인종·외형 설명에서 잘림과 간헐적 멈춤이 있었다고 확인했습니다. 자료는 이전 HRP 수정본을 적용하기 전의 것으로, 수정본에서의 재발을 확인한 자료는 아닙니다.

공식 sfall 4.5.1의 `HeroAppearance.cpp::CreateWordWrapList`는 게임의 공통 줄바꿈 함수를 사용하지 않고 바이트별 문자 폭으로 줄 목록을 만듭니다. CP949 두 바이트 한글을 개별 문자로 측정하면 실제 출력 폭과 줄바꿈 폭이 달라집니다. 특히 긴 장발·대머리 설명은 이 경로를 거칩니다. Windows 11이나 PC 사양 문제로 확정할 근거는 없습니다.

v1.2.4는 확인된 함수의 실행 중 진입점만 CP949 픽셀 폭 기반 어댑터로 연결합니다. sfall 자체 파일은 덮어쓰지 않습니다. 연결 목록은 sfall의 원래 할당 함수를 사용해 생성하므로 해제할 때 CRT가 섞이지 않습니다. 모든 노드와 마지막 sentinel을 초기화하며 설명을 요약하거나 삭제하지 않습니다.

대상은 공식 sfall 4.5.1(`ddraw.dll` SHA-256 `02469e78c6132010946612ec17cf4bd087aafa85a4485767fae7fba3a4151d24`)입니다. PE 식별 정보와 함수·호출 지점·메모리 할당 함수의 코드 지문이 맞아야 연결합니다. 다른 버전이나 이미 수정된 함수에는 강제로 연결하지 않습니다. 일반 한글 출력은 기존대로 동작하나, 다른 sfall 버전의 외형 창 수정까지 보장하지 않습니다.

## 검증

- x86 DLL 및 실제 fastcall 어댑터 호출을 컴파일하고 검사했습니다.
- RPU의 실제 외형 설명 13개를 돋움 11로 줄바꿈하여 각 줄 160px 이하, CP949 문자 경계 유지, 원문 전체 보존을 확인했습니다. 모두 4~9줄로 기존 카드의 11줄 안에 들어갑니다.
- 짧은 설명의 노드 초기화를 1,000회 반복 검사했습니다.
- 별도 RPU 실행본에서 새 DLL이 로드되고 sfall의 대상 함수가 새 어댑터로 연결된 것을 프로세스 메모리 읽기로 확인했습니다. `ddraw.dll` 디스크 파일은 원본 그대로입니다.
- 화면 자동화 도구가 게임 창의 소유자 연결 오류를 반환해 외형 반복 선택·영상 재생의 육안 확인은 완료하지 못했습니다. 멈춤 증상의 모든 원인이 해결됐다고 단정하지 않습니다.

## 업데이트

게임과 세이브를 백업하고 게임을 종료합니다. 기존 설치기의 복구 기능으로 이전 엔진을 복구한 다음 v1.2.4 설치기를 같은 게임 폴더에 적용합니다. RPU의 영상 자막은 별도 [RPU native.2 번역 패키지](https://github.com/munument1/Fallout2-RPU-KR/releases/tag/v2.4.34-native.2)를 먼저 덮어쓰세요. 영상 자막에는 `.sve` 파일이 필요하며 엔진만 업데이트해서 복원되지는 않습니다.
