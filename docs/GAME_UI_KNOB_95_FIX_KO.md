# Fallout 2 독립형 한국어 엔진: 원본 게임 기호 0x95 처리

2026-10-17 | 개발 브랜치 feature/selfcontained-korean-engine (PR #10 병합)

## 발견된 두 증상

- 하단 메시지창: 메시지 앞의 기호가 깨진 한국어 글자로 나타남
- NPC 대화 선택지: 선택지 앞에 원래 표시되어야 할 기호 대신 물음표가 나타남

## 원인

Fallout 2 원본 UI는 하단 메시지창과 대화 선택지에서 공통으로 **0x95
한 바이트 제어 기호**를 사용합니다.

- 공개 Fallout2 CE 소스 src/display_monitor.cc의 displayMonitorAddMessage 함수는
  각 메시지 첫머리에 0x95를 추가합니다.
- 공개 Fallout2 CE 소스 src/game_dialog.cc에서는 기본 대화 선택지의 맨 앞에
  0x95와 공백을 추가합니다.
- sfall의 NumbersInDialogue 설정이 1일 때만 이 기호 대신 실제 1., 2. 번호를
  선택지 앞에 붙입니다. 즉 물음표는 번호 자체가 아니라 **기호의 잘못된 출력**일 수 있습니다.

CP949에서 0x95는 동시에 DBCS의 선행 바이트로도 사용되므로,
모든 0x95를 무조건 하나의 특수기호로 교체하면 정상 한국어가 손상될 수 있습니다.
메시지 접두 기호 뒤에 한글이 이어질 때 두 바이트가 잘못 묶여
깨진 한국어 한 글자로 표시된 것이 실제 게임 화면에서 확인되었습니다.

## 수정

1. 글꼴 렌더러가 **문자열 시작의 게임 기호 0x95**와 나머지 유효한 CP949
   문자열을 분리하여 U+2022 불릿으로 표시하게 했습니다.
2. 정상 CP949 문자 내부의 0x95는 2바이트 그대로 보존합니다.
   예: 바이트 95 B0은 정상 문자로 다루며 접두 기호로 해석하지 않습니다.
3. 텍스트 너비 측정, 렌더링, SplitText 및 자체 wordWrap 훅에 같은 분리
   규칙을 적용해 측정·출력 간 글자 폭 불일치를 막았습니다.
4. 기존 0xFF UI 기호·한국어 글꼴·문장 줄바꿈 기능을 유지했습니다.

## 실증

- 독립형 32비트 DLL 컴파일 및 버퍼 가드·11,172자 한글 검사 통과.
- 게임 기호 단독, 기호+공백+한글, 기호+한글, 정상 CP949 두 바이트,
  실제 아라비아 숫자+한글의 상호 구분 검사 통과.
- 게임 실행 파일은 변경하지 않고 복사본의 DLL만 새 버전으로 교체한 뒤
  **하단 메시지의 기호와 한국어가 정상적으로 분리되는 화면 확인**.
- 사용자가 준비된 테스트 게임에서 **하단 메시지 기호와 실제 대화 선택지
  기호가 모두 정상 출력된다**고 추가 확인했습니다.
- 실제 RPU 한국어 대화문 12,000개 줄바꿈 검사 실패 0건.

**검증 범위:** NPC 선택지의 기호가 정상이라는 사용자 실게임 확인이
추가됐습니다. 다만 긴 대화문 전체 표시·다수 선택지 스크롤·선택 후 진행·
전투/핍보이 등 게임 전체 회귀 검사는 아직 별도로 수행해야 합니다.

## 대화 선택지를 숫자로 표시하는 방법

원본 불릿 표시 대신 숫자 번호를 원하면 게임 폴더의 ddraw.ini에서
Misc 섹션의 NumbersInDialogue 값을 1로 지정하면 됩니다.

    [Misc]
    NumbersInDialogue=1

NumbersInDialogue=0은 원본 기호 방식, 1은 1., 2., 3. 번호 방식입니다.
사용자의 기존 sfall 설정은 설치 과정에서 강제로 변경하지 않습니다.
